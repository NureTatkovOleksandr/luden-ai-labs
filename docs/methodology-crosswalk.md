# Зіставлення методичок і підготовка GitHub-репозиторію

Методичку Mini Issue Tracker надано користувачем під час підготовки публікації. Її прочитано як джерело процедурних вимог. Основна адаптована постановка й предметна область — Luden; рекомендований у прикладі FastAPI/SQLite, заявки й три стани не замінюють наявні .NET/React/Firebase та життєвий цикл замовлення Luden.

| Процедурна вимога Mini Issue Tracker | Артефакт Luden / виконання |
| --- | --- |
| Один репозиторій на всі чотири роботи | luden-ai-labs — спільний репозиторій навчальних артефактів; на цьому етапі опубліковано ЛР1. Наступні роботи продовжуються тут. |
| docs/requirements.md як джерело правил | Збережено канонічний контракт Luden, 8 початкових US/33 AC, пропозицію US-09, BR, ≥4 NFR і модель даних. |
| docs/architecture.md та щонайменше два ADR | Є модель сутностей, напрямки залежностей, відповідальності, ADR-01–03 і read-only точка ЛР4. |
| API-контракт із прикладами/помилками | Реальні API/DTO Luden та явно позначені пропозиції; жодного перенесення /issues. |
| Повна матриця переходів і PATCH | 25 комбінацій Luden; missing/null/empty/unknown/mixed помилки й атомарність; фактичні code gaps зафіксовані. |
| Traceability і чесне покриття | SRC→US→AC→BR→Component/API→TC; 33/33 початкових AC; метрики специфікації окремі від виконання продукту. |
| AI-журнал і короткий звіт 2–3 сторінки | docs/ai-log.md, docs/lab-01.md і PDF; джерела й історія збережені. |
| Фіксований tag або commit | Для здавання використовується lab01-spec-published. Попередні lab01-spec і lab01-spec-final — історичні, їх не пересунуто й не переписано. |
| Командне перехресне review | Пряме підтвердження користувача для всіх чотирьох учасників збережено; персональні findings/дати не вигадані. |
| Власний аналіз до AI та захист | Немає нового підтвердження; не підмінено створенням репозиторію. |

Ліміти «до 5 сутностей», два фіксовані користувачі, OPEN/IN_PROGRESS/CLOSED і приклад FR-01–FR-08 належать Mini Issue Tracker. Їх не перенесено в Luden; основні сутності User/Product/Bill/BillItem та допоміжні поля відповідають реальному коду. ЛР1 не вимагає реалізувати новий backend, запускати платежі чи переписувати стек.

Mini Issue Tracker DOCX (оригінал збережено в локальному комплекті), головна методичка Luden (оригінал збережено в локальному комплекті), [повна оцінка ЛР1](methodology-compliance.md), [структура репозиторію](../README.md).
